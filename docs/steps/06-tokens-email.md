## Design

**Token.** 32 random bytes -> 52-char lowercase base64url (no padding).
Generated by `tokens.New()`; stored as SHA-256 in `parties.token_hash`, with
`token_expires_at = min(now + expires_in, envelope.expires_at)`. The raw token
is never stored, never logged, never put in an `events` payload. Lookup is
`SELECT ... FROM parties WHERE token_hash = ?` — the only way a token resolves.

URL: `<SIGNSRV_PUBLIC_URL>/s/<token>`. Only `scheme`, `host`, `path` are
emitted; no query string carries a secret (no referrer leakage).

**Send** (`POST /envelopes/{id}/send`, requires `envelope:write`):

1. Envelope must be `ready` (else 409).
2. Re-issue tokens for any party whose token is missing/expired.
3. For each invited party, render the email and enqueue it
   (`mail_queue` handled by the worker, retried 5x with backoff; permanent
   failures mark `events: {kind:"mail_failed"}` and warn the admin, they do not
   fail the send).
4. `Transition(ready -> sent)`.

Email content (plain text + HTML, same copy):

```
Subject: Signature requested: {{title}}
Body:
  {{name}}, you are asked to sign "{{title}}".
  Reason shown at signing: {{reason}}
  You are party {{order}} of {{n}}.
  Sign: https://sign.example.org/s/<token>
  This link expires {{expires_at_local}} and is for {{email}} only.
  The document will be sent to all parties once everyone has signed.
  You can review the document before signing; you may decline.
```

No PDF attachment in the invite (the party reviews it on the signing page).
`List-Unsubscribe` header is **not** emitted — a one-click unsubscribe would
leak the token to mail proxies; the admin "cancel" path is the opt-out.

**Mail.** `signmail.Sender` interface with two implementations:
`smtpSender` (net/smtp with STARTTLS, auth LOGIN/PLAIN, 15s dial, 30s write) and
`fileSender` (writes `.eml` to `var/outbox`, used when `SIGNSRV_DEV=1`).
Subject and body escaping: text template escapes nothing (plain text), HTML
template escapes all interpolated fields with `html/template`. Address header
building uses `net/mail`-shaped quoting so a name with `"` cannot inject headers.
Header injection guard: reject any config/field containing CR or LF in the From
address, and reject newlines in `subject`/`message` at create time.

## Acceptance

```
go test ./internal/signflow ./internal/signmail
```

1. 10k `tokens.New()` calls: all unique, length 52, `token_hash` lookup round trip.
2. Expired token lookup returns `ErrTokenExpired` -> endpoint maps to 410.
3. Send on `ready` -> 2 `.eml` files in `var/outbox`, each containing exactly one
   `/s/<token>` URL and no PDF attachment; envelope is `sent`.
4. Send twice -> second call 409.
5. Party name `Bob"><script>` renders inert in HTML and does not break headers;
   a name containing `\r\n` is rejected at create.
6. `mail-test` sends one message through the configured SMTP and reports the
   SMTP code; in `SIGNSRV_DEV=1` writes to `var/outbox`.
